# Разработка игры в Godot

- Всю новую версию игры разрабатываем внутри `godot/`. Прежний Java/libGDX-прототип остаётся отдельно в корне репозитория.
- Движок: Godot 4.6, GDScript, рендерер Compatibility. Точка входа: `project.godot`. F5 запускает альбом `scenes/menu/main_menu.tscn`. Autoload `Journey` (`scenes/menu/journey.tscn`) отвечает за меню паузы, переходы и сохранение выбранной главы/бутылок. Три уровня находятся в `scenes/levels/` — для отдельного запуска открыть и нажать F6.
- Окружение, расстановку объектов, свет, камеры и коллизии сохраняем в редактируемых `.tscn`. Не генерируем уровень или геометрию скриптами при запуске.
- Скрипты отвечают за поведение и управление. Повторяемые объекты оформляем отдельными сценами.
- Все необходимые игровые ресурсы храним внутри проекта и используем пути `res://`. Готовые 3D-модели импортируем из GLB; Blender для запуска не требуется. Для 2D используем PNG и TileSet/TileMapLayer; пиксельная фильтрация на корнях сцен Полёта — Nearest.
- Не добавляем в Git `.godot/`, временные логи и сборки. Сохраняем `.import` и `.uid`.
- После изменений проекта проверяем импорт и запуск из корня репозитория:
  - `godot --headless --path godot --editor --import`
  - `godot --headless --path godot --quit-after 2`
- Изменения сцены дополнительно проверяем визуально; изменения управления и коллизий — прогулкой по уровню или подходящей проверкой физики. Успешная загрузка сама по себе не проверяет игровой процесс.
- Для изменений только в `godot/` проверки Java/Gradle из корневого `AGENTS.md` не требуются.
- Инструкция запуска и управления: `README.md` в этой папке. Объяснения пользователю — на русском.
